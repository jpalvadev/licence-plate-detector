# Recognition event identity is a plate track, not a plate string

Per-frame OCR is unstable by nature (chosen-char softmax ≈ 0.14 with confusable runner-ups: `D↔B`, `N↔X`), so the same car produces variant readings (`AD537NP`, `AD537XP`, `AB537XP`) within seconds — string-keyed dedup turned each variant into a new event, and symmetrically suppressed a second car showing the same string. We decided event identity is **object identity**: consecutive detections of the same box across detection passes form a **plate track** (association by IoU ≥ 0.3, surviving up to 3 undetected passes; stream loss closes all tracks), and one closed track = one Recognition event yielding exactly one Events log row, written at event **close** with the **plurality reading** of its sightings (validated readings preferred; ties broken by higher confidence).

This modifies ADR-0003: the row is written at event close, not at creation — the append-only, survives-restart guarantees are untouched, and `timestamp` still means first sighting. `DEDUP_WINDOW_S` is demoted from identity mechanism to a last-line guard: a closed event's exact string suppresses new rows within the window, plugging duplicate rows from split tracks.

Update (integration on the Test rig, same day): the ADR's parameters are the design baseline, not the tuned ones. On real 30 fps footage detector boxes for one plate jump around (plate-vs-bumper crops, partial occlusion), so raw IoU ≥ 0.3 fragmented tracks badly. Tuned defaults shipped in `.env.example`: IoU is computed on boxes **dilated by 50 % of their size on each side** (bridges box jumps; side-by-side cars still never associate), and `TRACK_MAX_MISSES` raised from 3 to 6 (~2 s at `DETECT_FPS=3`, bridging occlusion gaps in traffic). Both remain `.env` knobs.

Rejected: fuzzy string clustering as identity (text similarity is evidence, not identity — two queued cars with near-identical plates would merge); slot-wise majority voting across sightings (alignment cost across mixed-length readings, deferred for MVP); highest-confidence single sighting (lets one unstable frame decide the row); writing at first sighting (locks the log to the first, often wrong, reading).
