# Pragmatic yolo-v9-t detector despite GPL-trainer lineage

Research found no MIT-clean ONNX plate detector trained on plate data: the open-image-models `yolo-v9-t-384-license-plate-end2end.onnx` (7.6 MB, ~0.9 mAP, NMS inside the graph) is the only fast, small, ready-made option, but YOLOv9's upstream trainer (WongKinYiu) is GPL-3.0, so the weights sit in a license-lineage gray zone for an MIT repo. We accept it anyway: the app is LAN-internal, not commercially distributed, and training our own detector now would cost dataset labeling plus a training loop for marginal gain over 0.9 mAP, with heavier CPU inference (RF-DETR ~100+ MB; YOLOX fine-tune viable but slower to build). The caveat is documented in README and this ADR; the clean-lineage upgrade path (fine-tune Apache YOLOX-nano or RF-DETR-nano on the MIT arg-plates dataset plus the Apache synthetic Mercosur generator `vinihcampos/plates-generator`) stays available if strictness ever matters. Rejected: JustAnotherAlpr darknet yolov4-tiny MIT-declared AR-trained weights (23.5 MB but clunky non-ONNX inference, gray lineage too).
