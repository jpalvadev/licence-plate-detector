# PoC detector upgrade is an input-size tier, not a new architecture

For the personal-use PoC the licensing constraint was relaxed (no publishing, no commercial use), but research showed the relaxation unlocks nothing: no off-the-shelf plate detector beats the open-image-models yolo-v9 family, no pretrained OCR beats `cct_s_v2_global` on Argentine plates (PP-OCRv5, MMOCR ASTER, prebuilt TrOCR plate exports, Tesseract all measure lower), and anything past ~97% plate acc requires fine-tuning — which is off the table (no GPU, no training loop, Q5). The accuracy upgrade that does fit the constraints (CPU-only, ready-made weights, drop-in `PlateDetector` contract) is the **input-size tier within the same yolo-v9 zoo**: the default detector becomes `yolo-v9-s-608-license-plates-end2end` (mAP50-95 **0.772** vs 0.687 for the old `t-384`, recall 0.917 vs 0.863) while `t-640/t-512/t-416/t-384/t-256` stay selectable through `DETECTOR_MODEL`, each annotated with accuracy/size/CPU-latency in `.env.example` (Q8). Measured on the dev CPU (2026-10-21): s-608 ≈ 101 ms/pass vs 19 ms for t-384 — ~5x slower but still ~10 inferences/s against the 3 FPS budget's 333 ms/pass allowance, and on the identical 100 s `sample3.mp4` Test-rig window (mediamtx + ffmpeg RTSP feed) it logged 16 events / **15 distinct plate strings** vs t-384's 16 / 10 — full tables in `BENCHMARK.md`. OCR default unchanged: `cct_s_v2_global` (97.9% plate acc mean of upstream val; siblings 97.5/97.4/96.0% with their own .env comments).

This supersedes only the "only fast, small, ready-made option" claim in ADR-0004 — the family has six tiers, not one — while the YOLOv9 GPL-trainer lineage caveat applies unchanged to every tier. The server's real CPU was not benchmarked; if it starves at s-608, the step-down to `t-640` (0.758 mAP, ~58 ms on dev CPU) is a one-line `.env` change, not a code change.

Rejected: fine-tuned/GPU models (YOLO26n, RF-DETR, TrOCR plate fine-tunes, VLM OCR) — training and GPU are ruled out by the PoC constraints (Q1/Q2/Q5); COCO vehicle detectors (RF-DETR-coco, YOLO11-coco) as a plate-domain filter or dedup aid — dedup is already the plate track (ADR-0006) and vehicles are not the plate domain (ADR-0007); open-vocabulary detectors — no plate class without fine-tuning; swapping OCR to any sibling — every measured sibling is strictly worse for its cost.
