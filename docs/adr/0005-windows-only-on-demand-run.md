# Windows-only operation, started on demand (no supervision layer)

Both machines in play — the dev machine and the production server — run **Windows with Python 3.12.7**, so the app's setup/run/deploy procedures are Windows commands and no Linux/systemd variant is documented (the original "CPU-only Linux server" premise was wrong for this deployment). The app is started **manually** — open a terminal, run `python -m alpr` — with no service manager, Task Scheduler job, or NSSM wrapper: if the server reboots or logs out, the operator relaunches it by hand. Rejected: systemd unit (production is not Linux), NSSM / Task Scheduler auto-restart (nothing today requires keep-alive across a reboot — the append-only Events log per ADR-0003 survives restarts, so a manual relaunch loses nothing except the live stream), Linux appendix in the README (no Linux machine exists in the deployment). Consequences: README is Windows-only; the dashboard dies silently when the process is closed — an accepted state, not a crash; supervision can be added later without touching the app.
