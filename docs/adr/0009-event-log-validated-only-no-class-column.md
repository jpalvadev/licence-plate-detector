# The event log is validated-only, and the class column is a tautology to delete

ADR-0007 took motorcycles out of the domain entirely, which left the `vehicle_class` column (ADR-0008) with exactly two possible values — `CAR` for a Mercosur match, empty otherwise — telling the reviewer nothing the status column does not already say. Worse, most logged rows were not cars at all: ADR-0003/ADR-0006 had **every** closing plate track append a row, so split-box re-reads, non-AR plates and OCR garbage landed as `UNVALIDATED` and dominated both the CSV and the dashboard with triage noise. The operator wants the log to be exactly the Argentine cars: no entry unless the reading matches one of the configured formats.

Decision: the Events log is **validated-only**. When a closing track's consensus reading matches no format in the format set (empty `validation.classify` verdict), the track is simply dropped — no CSV row, no dashboard row, no console event. `UNVALIDATED` is no longer a status: the status set is exactly `VALIDATED_CAR` / `VALIDATED_LEGACY`, and `events.status_for` raises on a non format match (the tracker filters before calling; fail-fast, consistent with the config seams). The `vehicle_class` column is removed everywhere — CSV, dashboard, tracker row tuples — the Events log is `timestamp,plate,status,confidence`. The ADR-0006 dedup-window guard now registers only validated consensus strings, so garbage never poisons the guard.

Consequences: Paraguay/Peru 3+3 collisions stay `VALIDATED_LEGACY`, filterable by status as ADR-0008 documented — "no entry" applies to no-format matches, not to foreign plates sharing an active format. Unvalidated sightings are not lost: they still show as `? text` boxes on the live render and remain in the camera recording; only the log changes. The dashboard renders exactly two row styles (green car, amber legacy). Stale `events.csv` files with the old 5-column header are not migrated — the operator deletes them before restarting the app, so old and new columns never mix. ADR-0008's bad-OCR-combination caveat now degrades toward *no row*, not toward `UNVALIDATED` rows.

Rejected: keeping `UNVALIDATED` rows behind an optional flag (the operator does not care about them; render + recording already cover review); encoding class as always-`CAR` (a tautology); dropping unvalidated *sightings* from tracking (they legitimately vote alongside better sightings of the same box — only the logged row is affected).

Supersedes: the `UNVALIDATED`-row parts of ADR-0003/ADR-0006 and the `vehicle_class` column of ADR-0008.
